Three speech recognizers on meeting speech

Bashir Sadeghi · 25 November 2026 · Colab reproduction verified

I compared three automatic speech recognition (ASR) systems on 500 meeting-speech clips. Word error rate (WER)—word insertions, deletions, and substitutions divided by reference words—was 9.87% for FUTO, 13.67% for Whisper Turbo, and 14.12% for Whisper large-v3. Lower is better. Additional metrics and human listening revealed what WER misses.

01Recreate the leaderboard

I chose the Hugging Face Open ASR Leaderboard for its public evaluation data, scoring code, and dataset-specific results. I reproduce its AMI-Cleaned task: meeting speech from the Augmented Multiparty Interaction (AMI) corpus, suitable for examining hesitations and transcript fidelity.

The Whisper pair compares related systems; FUTO adds a connectionist temporal classification (CTC) recognizer with text correction and central processing unit (CPU) support. This is a comparison of shipped systems, not a controlled test of architecture alone.

Sampling: Of 7,805 test clips, 7,715 remain after excluding empty normalized references and scoring-ignore segments. I crossed their 16 meeting sessions with three global duration groups—short, medium, and long, each containing approximately one-third of eligible clips—to form 48 groups.

The workflow starts with 500 clips, sampled approximately in proportion to group size, with at least two per group. Seed 17 and pinned data fix the selection. All models process the same clips: 31.4 minutes of audio with 5,473 normalized reference words. Only selected clips require inference. Sources 1–2.

Estimate and uncertainty: Sample WER uses the 500 clips. Corpus WER estimates the eligible set by weighting each group’s errors and reference words using metadata group sizes. Resampling saved clip counts with replacement within groups 2,000 times gives approximate 95% intervals, without rerunning models.

What 500 supports: interval widths of 2.2–3.1 percentage points allow a broad comparison. FUTO’s interval lies below both Whisper intervals, supporting lower WER on eligible AMI under these configurations. The Whisper estimates are close and their intervals overlap; overlap does not establish equality. A paired interval for their WER difference has not been computed, so the current analysis does not establish a reliable Whisper winner.

Against the leaderboard: FUTO remains lowest; the Whisper pair reverses order. Sampling and runner settings differ, so this is an approximate reproduction. Configuration differences are detailed below.

Sampling, uncertainty, and model settings

Our FUTO tier is (256, 32); the reference runner specifies (256, 64), a different revision tag, and optimized execution. Sampling and inference settings could contribute to leaderboard differences; their individual effects were not isolated.

Global duration cutoffs are 2.0833 and 4.13 seconds. Duration groups are roughly equal across the full eligible set; they need not be equal within each meeting. Each group has a seeded permutation, so increasing sample size retains earlier clip identifiers. Selection uses metadata, not model errors. The stratified bootstrap applies population weights and a finite-population correction.

For finer comparisons, compute the WER difference using the same resampled clips for both models. If uncertainty remains too wide, extend the shared sample and predict only additional clips. Bootstrap assesses precision, not representativeness.

Intervals describe sampling uncertainty for this fixed eligible corpus under the tested configurations. They do not cover new meetings, reference errors, or environment changes. We did not run a paired significance test. The precision check is exploratory, not a prespecified stopping rule or a guarantee of 95% coverage under repeated sample-size decisions.

Accelerated inference uses NVIDIA graphics processing units (GPUs) through Compute Unified Device Architecture (CUDA).

02Test normalization

What changes? Normalization applies the same text-cleaning rules to the reference and prediction before scoring. For example, lowercasing makes “Hello” and “hello” match; keeping case counts that difference. I reuse the saved transcripts and change only the scoring rules.

Level 0: the leaderboard rules ignore case and most punctuation, remove hesitations such as “um” and “uh,” and standardize common spelling/name variants, number wording, contractions, and word spacing. Word insertions, deletions, and substitutions remaining after this cleaning still count.

Levels 1–8: progressively count more differences, keeping every earlier restriction. Level 1 counts hesitations; level 7 also counts case, and level 8 also counts punctuation.

What each level adds—and the limits of “strict”
LevelAdditional distinction counted
0Leaderboard
1Keep hesitations
2Keep name spellings
3Keep spelling variants
4Keep number wording
5Keep contractions
6Keep word spacing
7Keep case
8Keep punctuation

Each row adds to all previous rows. Level 6 also stops accepting compound-word spacing differences during scoring. Every level still removes non-speech annotations, standardizes Unicode and accents, and cleans whitespace, so level 8 is not an exact character-for-character comparison. WER need not increase at every step: text changes can alter word alignment and the number of reference words.

Select a level to update the table; the plot shows all nine. Character error rate (CER) counts character edits divided by reference characters.

Findings: at level 8, WER reaches 29.19% for Turbo, 29.41% for large-v3, and 20.32% for FUTO—about twice their leaderboard-rule scores. Counting hesitations alone adds 2.88 percentage points for Turbo, 2.80 for large-v3, and only 0.08 for FUTO. Punctuation produces the largest step. FUTO has the lowest WER at all nine levels.

Decision: use level 0 to compare with the leaderboard. Use stricter levels when the product needs exact wording or formatting. The changing scores show how strongly the evaluation depends on which differences count as errors.

03Look beyond WER

WER treats each word edit equally, so it can miss which changes matter most. I added CER for character-level errors and semantic distance as a proxy for changed meaning. A pinned MiniLM text encoder converts each transcript into a vector; distance is 1 − cosine similarity between the reference and prediction vectors. Source 3.

Decision: a product team choosing ASR for meeting notes can use metric disagreements to prioritize human review. No metric here verifies factual accuracy. I also conjectured that low CER despite high WER might identify promising fine-tuning candidates. This remains untested: CER alone cannot establish potential improvement from fine-tuning.

04Characterize the data—and check it

I measured duration, meeting session, and word density. Density is reference words divided by clip duration: 20 words in a 10-second clip gives 2 words/second. Pauses are included, so this is not pure speaking speed. “Raw” counts exclude non-speech annotations; “normalized” counts also apply level 0 rules.

Duration bins use sample thirds: ≤2.0633 s; >2.0633–4.1167 s; >4.1167 s. These descriptive bins differ slightly from the population bins used for sampling.

Finding: in this sample, all three systems have lower WER on longer clips. Clips with fewer reference words per second have the highest WER under both counting rules. These are associations, not causal conclusions: density and WER both depend on reference-word counts.

Reliability checks: all 500 identifier-derived durations match decoded audio lengths within one audio sample at 16,000 samples/second; no duration groups change. All 16 meeting labels match the session catalog. Switching from raw to normalized word counts changes the density group for 76/500 clips (15.2%). The overall low-density finding remains, but individual group assignments depend on normalization.

Human listening review: 10 matches, 2 reference omissions. From the evaluated 500 clips, I selected 3 shortest, 3 longest, 2 lowest-density, 2 highest-density, and 2 with the largest absolute density change after normalization. Selection used no predictions or WER. Two references omitted “tried a few times” and “things like that.” Scores retain the original references for leaderboard comparison.

Decision: use verified duration for segmentation and workload analysis; use density to flag clips for review. This targeted 12-clip check cannot estimate the overall reference-error rate.

How the 12 clips were selected, checks, and evidence

I ranked the 500 clips in five lists: shortest duration, longest duration, lowest normalized density, highest normalized density, and largest absolute difference between raw and normalized density (words/second). I took candidates from each list in turn, skipped duplicates, and stopped at 12 unique clips. Ties were resolved by clip identifier. Twelve was a practical listening budget, not a statistically determined audit size.

Session-catalog checks validate labels, not audio-to-session assignment. Metadata group comparisons have no subgroup uncertainty estimates, and differing utterance composition prevents causal conclusions. Descriptive duration bins use sample thirds, unlike the population bins used for sampling.

Human feedback was reported by Bashir; OpenAI Codex did not listen. Completed answers were carried forward to the Colab analysis only after all 12 clip identifiers and original references matched. No corrected-reference rescoring was performed.

Reproducibility, automation, and tool use

Full reproduction: Run predict for each of the three models, then evaluate. The README gives the four commands and setup. Predictions use the same 500 clips and pinned dataset and model revisions; new analyses go to runs/fresh/evaluation.html.

Check the included transcripts: Re-score the submitted Colab predictions without rerunning ASR:

python main.py evaluate --submitted

This may download the MiniLM text encoder and fetch missing audio for metadata checks. New analyses go to runs/recheck/evaluation.html; the submitted results remain available.

Automation

I would use one job, triggered by a model update or a regular schedule, to run these steps:

  1. Run the selected models on the fixed 500 clips and save each run separately with its model versions and settings.
  2. Check that every model has predictions for all the same clips, then run evaluate to generate the metrics, plots, and HTML reports.
  3. Compare scores with the previous run using the same scoring rules. Notify a reviewer if a run fails or a score changes beyond a predefined tolerance, and link to the report for investigation.

Prediction, completeness checks, and report generation already work. The job that launches these steps, compares runs, and sends notifications would need to be added. Listening to selected clips and interpreting flagged changes would remain human tasks.

My work and AI use

OpenAI Codex helped find sources, implement the workflow, diagnose failures, and draft this report. It checked saved transcripts and reproduced the 27 WER/CER score pairs and WER bootstrap intervals. Reference text came from the dataset; listening judgments came from a person.

I chose 500 shared clips and asked for a sample that could grow while reusing predictions. I proposed the normalization curve, reviewed the code and metric disagreements, and ran all three models and the full evaluation on Colab. When FUTO produced 401 empty transcripts on my Mac, I compared one clip on CPU and MPS, then reran the 500 clips on CPU. I arranged human listening review, reported two reference omissions, and kept the original references for leaderboard comparison.

Conclusion: FUTO is the strongest candidate for further testing on AMI under these configurations. This sample does not establish a reliable ranking between the Whisper pair, performance in other domains, or production readiness.
